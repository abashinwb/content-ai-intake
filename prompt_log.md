# Prompt log

Журнал фиксирует, как промпты из теории были адаптированы под собственный кейс Content AI. Полный личный чат для сдачи не требуется.

| Этап | Краткий промпт / запрос | Полученный результат | Ручное решение и проверка |
|---|---|---|---|
| P0. Выбор кейса | Использовать собственный сервис Content AI вместо демо-кейса рекламного агентства | Intake-портал обработки товарных Excel-каталогов | Сценарий ограничен одной обработкой файла |
| P1. Brief | Зафиксировать пользователя, задачу, успех и границы прототипа | Черновик структуры `prototype_brief.md` | Исключены кабинет, история, интеграции и реальный backend |
| P2. Карта экранов | Собрать минимальный путь из 4–6 экранов без лишних разделов | Четыре экрана: Старт, Загрузка, Проверка, Готово | Раздел `Правила` удалён; ветвления оставлены состояниями |
| P3. Intake-логика | Определить обязательные данные, блокировки и состояние нехватки данных | Обязательны задача и Excel; категория определяется автоматически | Добавлена проверка расширения и лимит 20 МБ |
| P4. Кликабельный каркас | Собрать автономный интерактивный прототип, который проходит от старта до подтверждения | HTML/CSS/JS-сайт без внешних зависимостей | Верхнее меню сделано кликабельным только для посещённых шагов |
| P5. Тексты | Написать деловые заголовки, подсказки, ошибки и подтверждение | Тексты собраны в `screen_copy.md` и перенесены в интерфейс | Старт заменён на `Начало работы`; добавлена согласованная сноска о конфиденциальности |
| P6. Тестирование | Подготовить три прохода и зафиксировать места остановки, ошибки и ожидания | Пройдены ветки заполнения, проверки и Figma | Критичных тупиков не найдено; честно отмечено отсутствие внешних участников |
| P7. Приоритеты | Разделить замечания на P1, P2 и `Позже` | P1 отсутствуют; P2 — проверка длинных заголовков и термина ЕАН | Реальный backend и интеграции отнесены к следующей итерации |
| P8. Handoff | Коротко описать готовое, сырое, пользу для W6 и W9 | Подготовлен `prototype_handoff.md` | Добавлена ожидаемая публичная ссылка GitHub Pages |

## Ключевые пользовательские уточнения

1. Стартовый заголовок: `Начало работы`.
2. Вводный текст: `Укажите задачу, загрузите Excel-файл с товарами и получите готовый результат.`
3. Три задачи: заполнение, проверка ошибок, шаблон для Figma.
4. Категорию Content AI определяет самостоятельно по содержимому Excel.
5. Раздел `Правила` не нужен.
6. На проверке обязательны категория и три цветных статуса.
7. Figma-ветка должна показывать нехватку данных и возврат к заполнению.
8. Финальный экран должен подтверждать скачивание и давать ссылку для повторной попытки.
9. Сайт публикуется отдельно от личного ChatGPT через GitHub Pages.

## Проверка результата

- основной путь прокликивается от первого экрана до подтверждения;
- три ветки имеют согласованные заголовки;
- будущие шаги меню заблокированы, пройденные доступны для возврата;
- состояние `Не все характеристики заполнены` имеет понятное действие;
- скачиваемые учебные файлы включены в архив;
- личные названия и адреса других проектов не используются.
